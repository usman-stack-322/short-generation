# Title to AI Short — configuration and workflow

Open http://127.0.0.1:5173/title-to-short after starting the existing API and Vite frontend. Choose a title, 30/45/60 seconds, English/Urdu/Roman Urdu, and educational/storytelling/documentary. Research creates a saved draft and stops at script review. Edit each scene narration and save, then choose **Render reviewed short**. Regenerate a scene's visual independently; narration cannot be changed by that action. Scripts are checked against fetched sources again on render. Previous renders and the football pilots are preserved.

Server configuration in backend/.env (restart the API after changes):

- GEMINI_API_KEY and GEMINI_MODEL: required for analysis, grounded script/scene planning and source audit. Existing bounded retry/fallback model configuration is reused. Missing keys, authentication, quota and service outages never produce demo success.
- TITLE_SHORT_SEARCH_PROVIDER=bing_rss (default) reuses the existing public search discovery integration. Public DuckDuckGo HTML is tried after RSS. Research requires at least two independently originating readable trusted sources; publisher/canonical/syndication/shared-original and near-duplicate groups count once. Search snippets are not evidence. TITLE_SHORT_SEARCH_PROVIDER=brave and BRAVE_SEARCH_API_KEY optionally use the official Brave API when public RSS discovery is unavailable. The key is sent only to its fixed official HTTPS endpoint. This does not activate a subscription or authorize purchases. See [Brave API documentation](https://api-dashboard.search.brave.com/app/documentation/web-search).
- Sources: the existing trusted-source registry, academic/government domains and a small explicit institutional allowlist. Private/local URLs and redirects outside the approved source host family are rejected. This conservative policy may reject topics; it fails explicitly instead of fabricating citations. Research excerpts, claim-to-source support and URLs are separate from the video.
- Visuals: existing Commons retrieval/license gates; optional PEXELS_API_KEY for the existing stock provider. A relevant unique licensed photo is required per scene. Per-scene prompts are provided, but AI image generation is not connected and is never presented as completed or archival evidence. No placeholder cards are rendered. Creator, license, URL and modifications are retained; final photo credits and research URLs are downloadable with the MP4.
- TITLE_SHORT_TTS_PROVIDER=local (default) uses reviewed local Kokoro bm_george for English if its cached runtime exists; otherwise a matching installed system narrator. Urdu/Roman Urdu require a compatible installed Urdu narrator. Missing voices are a clear blocker. TITLE_SHORT_TTS_PROVIDER=elevenlabs with TITLE_SHORT_VOICE=<allowlisted generic voice ID> can be explicitly configured only after service/voice authorization; the existing ELEVENLABS_API_KEY and ELEVENLABS_ALLOWED_VOICE_IDS apply. No automatic paid/cloud fallback occurs. Google is not offered here because its current adapter lacks native word timing. Cached Kokoro English-only presets cannot be used for Urdu.
- Roman Urdu narration text stays Latin and is passed to a compatible Urdu narrator; pronunciation must be reviewed. This feature does not promise automatic perfect transliteration or pronunciation.
- FFmpeg/FFprobe and existing language fonts are reused. Native script/audio-bound timestamps are mandatory. Complete narration must occupy 80% of the target and finish before the duration limit. A mismatch asks for a script edit; it never cuts off speech, speeds it up, or pads a long silent video.

Final output uses the existing clean 1080×1920/30 fps renderer, AAC audio, proportional images, restrained motion, clean transitions and box-free narration captions. Full decoding must pass before ready status. Local speech can be slow; saved stage progress remains visible. Restarted workers become failed/retryable rather than claiming completion. Only explicit render requests advance past review. Drafts are workspace scoped; editors see their own drafts, owners the workspace drafts. Preview/download uses existing authenticated HttpOnly media sessions, including Range support.

New additive migration: 0014_title_shorts. Automatic pre-upgrade SQLite backup is retained in backend/backups. The feature uses its own draft table and media root; it creates no UploadTask or existing pilot revisions. Uploads remain disabled.

AI JSON integration follows the existing Gemini adapter and [official structured output documentation](https://ai.google.dev/gemini-api/docs/generate-content/structured-output). Source checking is an automated evidence audit with exact excerpt checks, not a guarantee of truth; human factual and listening review remains necessary.

Individual-scene controls: **Regenerate this scene visual** preserves narration; **Rewrite only this scene** rewrites only the requested scene against the original sources, rejects changes to other scenes, and returns to script review. Rendering always remains an explicit separate action.

## Live acceptance update — 29 October 2026

The verified English live Short is now available: http://127.0.0.1:5173/title-to-short/97e2bfd4-2c9b-4144-ab64-f410062a05b7 . See TITLE_TO_SHORT_LIVE_ACCEPTANCE_REPORT.md for the actual sources, narrator and playback/technical evidence.

Source URL inputs accept up to six reliable public HTTPS article URLs. They undergo the same trusted-host, public-address, bounded HTML/readability, independent-origin, source-owned-passage and script audit checks as automatic discovery. Research retries preserve edited scripts/assets/render history. A preserved plan must pass the new evidence audit before rendering; latest failed research blocks rendering. Retrieval diagnostics expose each query, candidate rejection and article failure. No search snippet is counted as source evidence.

The narrator selector supports automatic, installed local or reviewed Kokoro. Both UI capabilities and server endpoints reject unavailable language/narrator combinations before allocating generation work. This installation has no Urdu/Roman Urdu system narrator; install a compatible narrator or explicitly configure an authorized allowlisted multilingual voice before using those languages.

The title-only model can be selected with TITLE_SHORT_AI_MODEL; it is restricted to the already configured GEMINI_MODEL/GEMINI_FALLBACK_MODEL. The live run used the already configured fallback after primary-model 503/timeouts and quota errors. Global Gemini settings are preserved. Mandatory factual auditing remains enabled.

Licensed clean-source workspace photos may be reused for the matching subject when their recorded rights/real-photo flags and permitted license pass. Workspace/channel access applies; originals remain read-only and duplicate hashes are excluded. This is an archival illustrative-photo path, never a claim of award-event footage or a newly generated AI image.

## Automatic incident research update — 29 October 2026

Read TITLE_TO_SHORT_AUTOMATIC_RESEARCH_REPORT.md. Sensational titles are unverified leads, neutral entity queries are searched, and public YouTube oEmbed is metadata only. Legally public trusted publisher podcast transcript URLs are supported; absent transcripts are explicit. Incident claim support uses actual server-indexed source passages from independent groups; unverified title quotes are excluded. AI schema/excerpt failures are distinguished from insufficient evidence. Default retries rediscover sources without losing saved edits; an explicit retry query refresh_sources=false rechecks fetched evidence. Optional request_id enables scoped, race-safe idempotent creation; stale revision actions are rejected. No new service subscription or upload capability was added.

## Claim-level scope review — 29 October 2026

Qualifying independently supported claims can now form a narrower draft even if other headline elements are unsupported. The original title remains stored; script review shows a proposed accurate title/focus and explicit omissions. Paraphrases supported by readable reporting do not require transcripts. Direct spoken quotations require original recording/transcript evidence plus existing corroboration checks, or are omitted. No qualifying coherent script yields a precise error.

The user must explicitly accept the revised scope/current saved script before rendering. POST /api/title-shorts/{id}/scope/accept requires the current revision and a verified script_review state; both render API and worker enforce content/source-bound acceptance. Editing or renewed evidence changes require acceptance again. Saving script edits preserves prior plans in script_history; research_history retains previous scope/evidence snapshots. Read TITLE_TO_SHORT_CLAIM_SCOPE_REPORT.md for the actual live draft and its supported script; no video was produced during scope review.
