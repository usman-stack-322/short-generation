## Implemented

- **Media Library** navigation/page: private collections, explicit channel assignment/sharing, photo/clip/audio/brand-image uploads, authenticated previews, name/tag search, media-type and approval filters, metadata editing, manual approval, safe archival and usage counts. Library files never use supplied filenames as disk paths. MIME/type checks, bounded reads, image decoding/dimensions, FFprobe validation, protocol restrictions and collection-scoped SHA-256 uniqueness protect uploads. Concurrent duplicate submissions reuse one row; private collection hashes/results are not exposed to unauthorized members.
- Approved photos and clips match an exact personality ID. Tags are searchable metadata, not sufficient subject-identity evidence. The uploader explicitly attests reuse permission and subject identity; reviewers must approve uploads before automatic selection. This does not claim machine verification of an uploaded photograph's identity or authenticity.
- **Auto Research / Hybrid / My Assets** modes in Create Short. Hybrid is recommended and selects approved media from the chosen channel collection before online retrieval. Without a browser selection, the backend resolves an accessible, assigned collection containing matching approved media; daily preparation benefits too. Auto Research preserves the existing provider path. My Assets does not search online for media; uncovered scenes use labeled neutral text cards. Every mode still uses the existing factual verification gates. Saved script editing/regeneration remains available; this change does not introduce unverified news generation from uploaded media.
- **Avoid recently used** prefers least recently used eligible media. Successful-render usage is unique by asset/job/media revision. Failures do not record usage. Each selected asset is copied into the job's own media directory with a provenance/credit snapshot. Removing a library asset archives it for future selection; source files and existing job copies remain available.
- Collection audio previews are distinct from generated voiceover previews. Owners may explicitly share an approved audio copy into the existing workspace background-music pool, then select it in Settings. Uploads can be previewed before saving. Library audio is not silently substituted for narration. Brand images are stored and previewed, not automatically overlaid on every export.
- **Dashboard** prioritizes Ready for Review, Needs Attention, Scheduled Today and Next Upload. A persisted run sheet shows channel/topic/stage/schedule/next action. Operational information is separate from authorized audience analytics. No synthetic performance metrics or invented processing durations are shown. Existing queue history filters, error details, reconnect actions and stage-specific retries remain in use.
- **Settings / Channel defaults and presets**: editable sports news/commentary/business presets; language, narrator, voice style, duration, template, IANA timezone, posting window, minimum gap, visibility and approval policy. New manual/OAuth channels inherit saved defaults. Existing channels require an explicit selection, proposed-change preview and confirmation. Regular Settings saves preserve these defaults. Create Short applies per-channel duration/template defaults; publishing confirmations use channel visibility/timezone defaults. Existing jobs remain unchanged. Schedule validation checks posting windows and minimum gaps against persisted channel schedules. Existing durable preparation operations and upload-task duplicate guards remain intact. Existing preparation enable/pause settings were reused; uploads stay disabled.
- **Review**: choose an approved saved photo, retain online replacement/removal/upload controls, arrange photographs across narration slots, change scene duration and motion focal points. Layout changes atomically invalidate the current render and approvals; stale/concurrent revisions are rejected. Scene durations must total the selected Short duration. Narration order is deliberately preserved when rearranging photographs.
- **Renderer**: approved clips loop as visual input with clip audio excluded in favor of narration; retained 1080x1920 H.264/AAC, crossfades, subtitles, proportional padding and background-music ducking. Focal points affect restrained photo motion; no face edits or arbitrary destructive crop. Dynamic normalization handles silent development audio without NaN/AAC failures. Existing Urdu/Arabic subtitle shaping is retained.

## Current bounds / setup

- One collection is assigned to one channel at a time; each job selects one collection. A channel can have several collections. Automatic resolution chooses the oldest accessible collection containing approved matching media. It does not combine assets across multiple collections.
- Upload licensing/identity is an explicit human attestation, not an authenticity guarantee. Sources, dates and research verification remain independently necessary. Archive labels prevent an uploaded subject photo being represented as evidence of a specific current event.
- Brand assets are organized/previewed; no automatic brand-overlay designer was added. Scene rearrangement moves visual assignments rather than rewriting narration. Focal adjustment uses the existing padded gentle-motion treatment rather than destructive image cropping.
- There is no new free-text supplied-script import form. The retained generation and saved-script editor provide the generated-script path in all modes; changing a saved script still invalidates narration/render approvals.
- No new production analytics sync or real YouTube/OAuth test was required or performed. Existing tests and permission guards remain. Uploads are disabled, even when a local schedule is saved.
- Local backend/worker must be running for preparation/schedules. Existing operation keys prevent daily preparation duplicates after restart. Existing media-session behavior retains the project's localhost same-site deployment assumptions.

## User guide

1. Open **Media Library → Create collection**, enter a subject/topic name and assign the intended channel. Unassigned collections remain private; assignment shares reading with members authorized for that channel. Only the collection owner/workspace owner may edit it.
2. Open **Upload reusable media**. Choose the real photo/clip, correct personality, creator, source and permission/credit information. Preview the selected file, attest identity/reuse permission, then upload. Review each entry and check **Approved identity and reuse permission → Save review**.
3. Open **Create Short**, choose the channel/personality and **Hybrid (recommended)**. Select the collection, or allow automatic matching. Keep least-recently-used preference if desired. Select a verifiable story and generate normally. My Assets avoids online media search, but never skips factual verification.
4. Review sources, dates, script, generated narration and scene media. Use **Choose saved photo** for replacement or **Arrange scene photos and timing** for visuals/timing. Save and regenerate video after edits; fresh approval is required. Preview and use **Download MP4**. Publishing remains disabled.
5. Owners configure future channel inheritance under **Settings → Channel defaults and presets**. To update existing channels, select them, preview proposed changes and explicitly confirm. Collection assignment stays in Media Library.
